# Current AI setup and verification status

Current configuration selects Hugging Face's local EmbeddingGemma 2 safetensors model for image/text embeddings and Ollama Cloud Gemma 4 for chat/VLM. Google Gemini and OpenRouter remain optional embedding/chat providers; Gemini visual checks still use the Google key. Keep every key on the backend; never return it in health, errors, fingerprints or fixtures. Provider changes create incompatible vector spaces and require full reindexing. OpenRouter's selected free embedding model may log prompts/outputs, so it must not receive sensitive footage.

## Ollama EmbeddingGemma 2

`HuggingFaceEmbeddingAdapter` loads `google/embeddinggemma-2` directly through Sentence Transformers and Transformers, pinned to revision `914f7f89142e33e77833254d9c9b90c3cef7303b`. The model card documents unified 768-dimensional text/image/video/audio embeddings and multimodal interleaving. `HF_AUTO_DOWNLOAD_EMBEDDING=true` lets the library fetch missing checkpoint files into the Hugging Face cache during startup; false requires a complete local cache. Text uses the `SearchQuery` instruction. For an 8-second source window, FFmpeg samples up to eight chronological JPEG frames, and the adapter embeds them together as one text-plus-image input rather than averaging independent image vectors. Audio weights are omitted to reduce memory; CUDA is selected when available and CPU is the fallback. The API smoke-tests both text and image embedding before advertising semantic search. Chat/VLM uses `gemma4:31b-cloud` separately and sends selected frames to Ollama Cloud. Sources: [Hugging Face model card](https://huggingface.co/google/embeddinggemma-2) and [Transformers model documentation](https://huggingface.co/docs/transformers/model_doc/embedding_gemma2).

## OpenRouter image-and-text embeddings

`OpenRouterEmbeddingAdapter` uses the official OpenAI Python SDK against `https://openrouter.ai/api/v1/embeddings`, model `nvidia/llama-nemotron-embed-vl-1b-v2:free` by default. It samples up to eight JPEG frames at 1 FPS from each indexing window, sends the images and a clip description as one multimodal document, and normalizes the single returned clip vector. Search queries use text-only embeddings from the same model. The adapter obtains and records the model's actual vector dimension at load; the fingerprint captures model, dimension, sampling/preprocessing and SDK version. `OPENROUTER_API_KEY`, `OPENROUTER_BASE_URL`, and `OPENROUTER_EMBEDDING_MODEL` configure it. Live OpenRouter calls have not been tested because the local backend environment currently has no OpenRouter key.

## Ollama/OpenAI-compatible chat and vision

`OpenAICompatibleChatAdapter` uses the OpenAI Python SDK and OpenAI-compatible `/v1/chat/completions`, with validated backend tool calls and image inputs for VLM answers. Defaults are `CHAT_PROVIDER=ollama`, `CHAT_BASE_URL=http://localhost:11434/v1`, `CHAT_API_KEY=ollama`, and `CHAT_MODEL=gemma4:31b-cloud`. Ollama local-server usage requires the daemon signed into the user's Ollama account; direct cloud use sets `CHAT_BASE_URL=https://ollama.com/v1` and `CHAT_API_KEY` to the backend-only Ollama API key. Tool-call and one-frame vision smoke tests passed against the local Ollama cloud model. Current Ollama documentation describes the `/v1/chat/completions` endpoint and local cloud-model access; model compatibility can vary.

## Gemini Embedding 2

Official sources reviewed 8 October 2026: [embedding documentation](https://ai.google.dev/gemini-api/docs/embeddings) and [Google Gen AI Python SDK](https://googleapis.github.io/python-genai/). Runtime `google-genai==2.29.0` is installed and its real request/response Pydantic types are tested.

`GeminiEmbeddingAdapter` uses configurable model ID `gemini-embedding-2`, requests 768 dimensions, validates finite shape and normalizes vectors for cosine retrieval. Text queries receive `task: search result | query: ...`; the request omits the unsupported `task_type` field. Video uses MP4 inline data. The API supports up to 120-second videos; this application bounds windows to eight seconds, transcodes H.264 without audio at 1 FPS and maximum 640-pixel dimensions, and limits raw inline bytes to 14 MiB to leave room for base64 under a 20 MB request. Oversized inputs fail explicitly.

The adapter requires two text queries and a generated one-second video smoke request before capability becomes true. These startup checks make three billable API calls when enabled with a key. Requests use a 60-second timeout and one SDK attempt. Clients close on load failure/shutdown. Service errors suppress SDK exception text. Live text/video smoke requests passed with finite 768-dimensional vectors; two generated geometric videos were actually indexed and retrieved through the HTTP API. Their tiny synthetic development evaluation is reported in README and is not a CCTV accuracy estimate. Regression tests use mocked API responses and real FFmpeg. Sparse sampling and resizing can miss brief events or small bags. Persist `adapter.fingerprint`; changes to providers, models, dimensions, SDK or preprocessing invalidate existing indexes. Google model IDs are API identifiers rather than immutable checkpoint hashes.

## Gemini chat

The default chat model is `gemini-3.5-flash`, configurable on the backend. It uses the same key and installed SDK as embedding. Manual function calling preserves model content and thought signatures. Tools are validated and limited to selected recordings, with a maximum of eight model rounds and three searches per turn. Primitive provider schemas avoid reference-resolution ambiguity while full Pydantic validation remains enforced on responses. Low thinking is requested, with up to 4096 output tokens and one SDK attempt. The final `finish_response` selects real result references; the backend renders their evidence without publishing unconstrained model claims. The additional function-call startup smoke test is billable. Messages, follow-up context and turns persist in SQLite. Live Gemini 3.5 smoke/tool calls, grounded explanation and time-filter follow-up passed. An earlier follow-up failed visibly before successful resubmission. Gemini 3.8 smoke attempts produced server errors; the tested 3.5 model is the explicit default, with no silent model fallback.

## Upstream recovery

Sanitized MODEL_UNAVAILABLE errors expose provider_status and retry_after_sec. Health capabilities are false during transient cooldowns. Runtime adapters recover after cooldown; failed startup smoke checks retry in the background only when due. Google429 defaults to60seconds, temporaryserverfailures15seconds, bounded Retry-After1–300seconds. Quota/billing capacity is external; cooldown does not claim to restore exhausted daily quota.

## General visual chat

Natural visible-detail questions use Gemini image inputs from chat-owned retrieved clips, separate from the narrow bag checker. Structured answers cite supplied frame IDs; timestamps and media paths are resolved server-side. Follow-ups retain context. The VLM may describe visible object positions/colors but cannot establish identity, ownership, intent or off-camera facts. Valid citations constrain provenance; they do not guarantee model correctness. Official implementation references: https://ai.google.dev/gemini-api/docs/image-understanding and https://ai.google.dev/gemini-api/docs/function-calling .
