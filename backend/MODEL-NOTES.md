# Current AI setup and verification status

The selected stack is Google Gemini chat and Google Gemini Embedding 2 through the Google API, sharing backend-only `GEMINI_API_KEY`, plus Gemini visual frame checks. Keep the key in the environment; never return it in health, errors, fingerprints or fixtures. Cloud embedding sends selected recording windows to Google; visual-check frames also go to Google.

## Gemini Embedding 2

Official sources reviewed 8 October 2026: [embedding documentation](https://ai.google.dev/gemini-api/docs/embeddings) and [Google Gen AI Python SDK](https://googleapis.github.io/python-genai/). Runtime `google-genai==2.29.0` is installed and its real request/response Pydantic types are tested.

`GeminiEmbeddingAdapter` uses configurable model ID `gemini-embedding-2`, requests 768 dimensions, validates finite shape and normalizes vectors for cosine retrieval. Text queries receive `task: search result | query: ...`; the request omits the unsupported `task_type` field. Video uses MP4 inline data. The API supports up to 120-second videos; this application bounds windows to eight seconds, transcodes H.264 without audio at 1 FPS and maximum 640-pixel dimensions, and limits raw inline bytes to 14 MiB to leave room for base64 under a 20 MB request. Oversized inputs fail explicitly.

The adapter requires two text queries and a generated one-second video smoke request before capability becomes true. These startup checks make three billable API calls when enabled with a key. Requests use a 60-second timeout and at most two SDK attempts. Clients close on load failure/shutdown. Service errors suppress SDK exception text. Live text/video smoke requests passed with finite 768-dimensional vectors; two generated geometric videos were actually indexed and retrieved through the HTTP API. Their tiny synthetic development evaluation is reported in README and is not a CCTV accuracy estimate. Regression tests use mocked API responses and real FFmpeg. Sparse sampling and resizing can miss brief events or small bags. Persist `adapter.fingerprint`; changes to providers, models, dimensions, SDK or preprocessing invalidate existing indexes. Google model IDs are API identifiers rather than immutable checkpoint hashes.

## Gemini visual decisions

The user selected Gemini in place of the unavailable Laya runtime. `GeminiVerificationAdapter` uses `gemini-3.5-flash` (configurable via GEMINI_VERIFICATION_MODEL) and the same backend key. A billable structured image smoke must pass before capability becomes true. Bag presence and person-carrying-bag checks return yes/no/uncertain, with `probability_yes: null`. Readability gates prevent decisions on poor frames. Explicit SDK schemas avoid unsupported additional-properties fields. Requests have a 60-second timeout and two bounded attempts. Live image smoke passed; a red square returned no bag. Staged CCTV evaluation remains outstanding.

## Gemini chat

The default chat model is `gemini-3.5-flash`, configurable on the backend. It uses the same key and installed SDK as embedding. Manual function calling preserves model content and thought signatures. Tools are validated and limited to selected recordings, with a maximum of eight model rounds and three searches per turn. Primitive provider schemas avoid reference-resolution ambiguity while full Pydantic validation remains enforced on responses. Low thinking is requested, with up to 4096 output tokens and two bounded SDK attempts. The final `finish_response` selects real result references; the backend renders their evidence without publishing unconstrained model claims. The additional function-call startup smoke test is billable. Messages, follow-up context and turns persist in SQLite. Live Gemini 3.5 smoke/tool calls, grounded explanation and time-filter follow-up passed. An earlier follow-up failed visibly before successful resubmission. Gemini 3.8 smoke attempts produced server errors; the tested 3.5 model is the explicit default, with no silent model fallback.
